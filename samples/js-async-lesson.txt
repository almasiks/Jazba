[00:00] Ментор: Так, всем привет, ну что, начинаем. Слышно меня нормально? Окей. Сегодня у нас тема — асинхронность в JavaScript. Это, короче, одна из самых важных тем, на собесах её прям любят спрашивать. Будем разбирать callbacks, Promise и async/await.

[01:10] Ментор: Смотрите, JavaScript — он single-threaded, то есть однопоточный. Он выполняет код строчка за строчкой, по одной задаче за раз. Вот представьте, если у нас запрос на сервер идёт три секунды, и всё это время страница просто висит — кнопки не нажимаются, ничего. Это плохо. Поэтому долгие операции — запросы, таймеры, чтение файлов — делаются асинхронно.

[02:30] Ментор: Давайте пример. Пишу:
console.log("1");
setTimeout(() => console.log("2"), 0);
console.log("3");
Как думаете, что выведется? ... Да, многие думают 1, 2, 3. А на самом деле 1, 3, 2. Даже с нулём миллисекунд.

[03:05] Студент: А почему так, если там ноль стоит?

[03:10] Ментор: Хороший вопрос. Потому что setTimeout не выполняет функцию сразу. Он отдаёт её браузеру, браузер ждёт таймер и кладёт callback в очередь — callback queue. А event loop берёт задачу из очереди только тогда, когда call stack пустой. То есть сначала весь синхронный код доработает — 1 и 3 — и только потом 2. Ноль — это минимальная задержка, а не «прямо сейчас».

[05:00] Ментор: Окей, теперь callbacks. Callback — это просто функция, которую мы передаём в другую функцию, чтобы её вызвали потом, когда что-то закончится. Например:
function loadUser(id, callback) {
  setTimeout(() => callback({ id, name: "Aida" }), 1000);
}
loadUser(1, (user) => console.log(user));
Проблема в том, что когда надо сделать несколько шагов подряд — загрузить юзера, потом его посты, потом комментарии — получается вложенность в вложенность. Это называют callback hell, или pyramid of doom. Читать невозможно, ошибки обрабатывать тоже неудобно.

[08:20] Ментор: Поэтому придумали Promise. Promise — это объект, который представляет результат асинхронной операции, которого ещё нет, но он будет. У него три состояния: pending — ожидание, fulfilled — успешно выполнен, и rejected — ошибка. Мен бұны тақтаға жазып қоямын — pending, fulfilled, rejected. Из pending он переходит один раз, и всё, назад уже не меняется.

[09:40] Ментор: Создаём так:
const promise = new Promise((resolve, reject) => {
  setTimeout(() => resolve("Готово"), 1000);
});
promise
  .then((result) => console.log(result))
  .catch((error) => console.error(error));
resolve переводит в fulfilled, reject — в rejected. then срабатывает при успехе, catch ловит ошибку. И главное — then можно чейнить, цепочкой, и вложенности больше нет.

[12:15] Студент: Ағай, а если в середине цепочки ошибка, catch в конце её поймает?

[12:25] Ментор: Да, поймает. Ошибка как бы «проскакивает» все следующие then и падает в ближайший catch. Поэтому обычно одного catch в конце цепочки достаточно.

[13:30] Ментор: Теперь async/await — это, по сути, синтаксический сахар над промисами. Код выглядит как синхронный, а работает асинхронно. Пишем async перед функцией — и она всегда возвращает Promise. А внутри можем писать await — он ставит функцию на паузу, пока промис не выполнится.
async function showUser() {
  try {
    const response = await fetch("/api/user");
    const user = await response.json();
    console.log(user);
  } catch (error) {
    console.error("Ошибка:", error);
  }
}
Ошибки здесь ловим обычным try/catch.

[16:00] Студент: А await можно использовать в обычной функции, без async?

[16:05] Ментор: Нет, внутри обычной функции будет SyntaxError. await работает только внутри async-функции. Ну, ещё есть top-level await в модулях, но это отдельная история, пока не заморачивайтесь.

[17:10] Ментор: И последнее на сегодня — Promise.all. Если у нас несколько запросов, которые друг от друга не зависят, не надо их ждать по очереди. Делаем так:
const [users, posts] = await Promise.all([fetchUsers(), fetchPosts()]);
Они идут параллельно, и мы ждём, пока выполнятся все. Но если хотя бы один упадёт — весь Promise.all уйдёт в rejected.

[19:00] Ментор: Всё, на сегодня всё. Дома потренируйтесь: перепишите пример с callback на промисы, а потом на async/await. В следующий раз будем делать запросы к реальному API. Сұрақтар болса, чатқа жазыңыздар. Пока!
