Ментор: Всем привет, сегодня разбираем состояние в React — хук useState. Это то, без чего ни один интерактивный компонент не работает.

Ментор: Начнём с проблемы. Допустим, у нас счётчик: let count = 0, и кнопка, которая делает count = count + 1. Нажимаем — а на экране всё ещё ноль. Почему?

Студент: Потому что React не знает, что переменная поменялась?

Ментор: Да, бәрекелді. Обычная переменная живёт только внутри одного вызова функции-компонента. React не следит за ней и не перерисовывает компонент. Плюс при следующем рендере она снова станет нулём.

Ментор: Для этого есть useState. Пишем: const [count, setCount] = useState(0). Ноль — начальное значение. count — текущее значение, setCount — функция, которая его меняет и говорит React: перерисуй компонент.

Ментор: Квадратные скобки — это деструктуризация массива. useState возвращает массив из двух элементов, и мы сразу даём им имена. Называть можно как угодно, но принято value и setValue.

Студент: А можно просто написать count = 5 вместо setCount(5)?

Ментор: Нельзя. Это частая ошибка новичков. Если присвоить напрямую, React ничего не узнает, и экран не обновится. Состояние меняем только через сеттер.

Ментор: Второй важный момент — setCount не меняет count мгновенно. Смотрите: если в одном обработчике написать setCount(count + 1) три раза подряд, счётчик увеличится только на один.

Студент: Почему на один, а не на три?

Ментор: Потому что во всех трёх вызовах count — это одно и то же старое значение из текущего рендера. Ноль плюс один, ноль плюс один, ноль плюс один. React объединяет обновления и делает один рендер.

Ментор: Решение — функциональное обновление: setCount(prev => prev + 1). Тогда React передаёт в функцию самое свежее значение, и три вызова дадут плюс три. Правило простое: если новое значение зависит от старого — используйте функцию.

Ментор: Теперь про объекты и массивы. Допустим, состояние — объект user с полями name и age. Если написать user.age = 20 и потом setUser(user), ничего не перерисуется.

Студент: Это потому что ссылка та же самая?

Ментор: Точно. React сравнивает старое и новое значение по ссылке. Объект тот же — значит, для React ничего не поменялось. Поэтому создаём новый объект: setUser({ ...user, age: 20 }). Спред копирует старые поля, а age перезаписываем.

Ментор: С массивами то же самое. Не push, а setItems([...items, newItem]). Не splice, а filter. Не изменять элемент по индексу, а map, который возвращает новый массив. Это называется иммутабельность — мы не мутируем состояние, а заменяем его.

Студент: А если начальное значение тяжело считать, например читать из localStorage?

Ментор: Тогда передавайте в useState функцию: useState(() => loadFromStorage()). Она вызовется только при первом рендере. Если написать useState(loadFromStorage()), функция будет вызываться на каждом рендере, просто результат будет выбрасываться.

Ментор: И последнее на сегодня: где хранить состояние. Если два компонента должны видеть одни и те же данные, состояние поднимают в их общего родителя и передают вниз через props. Это называется lifting state up.

Студент: А почему не сделать отдельный useState в каждом компоненте?

Ментор: Тогда у вас будет две независимые копии данных, и они разъедутся. Один источник правды — одно место, где хранится значение.
